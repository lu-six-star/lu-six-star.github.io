Rust 生命周期学习

一、什么是生命周期

生命周期描述的是引用有效的时间范围。每个引用在创建时都会绑定一段生命周期，这段生命周期不能超过它指向数据的生命周期。如果引用试图指向一个已经失效的数据，Rust 的借用检查器会在编译阶段直接报错。

可以从两个角度理解：

  • 代码作用域角度：变量从声明开始有效，到离开作用域结束。
  • 引用安全角度：引用本身必须在被引用数据的有效期内才能使用。

Rust 并不是真的在运行时跟踪生命周期，生命周期只是编译器用来验证引用合法性的静态约束。

四、生命周期省略规则

并不是所有函数都需要显式标注生命周期。Rust 为了方便书写，定义了生命周期省略规则（Lifetime Elision Rules）。编译器会按以下三条规则自动推导：

  1. 每个引用参数都有自己的生命周期参数。
  2. 如果只有一个输入生命周期参数，那么它会被赋给所有输出生命周期参数。
  3. 如果有多个输入生命周期参数，但其中一个是 &self 或 &mut self，那么 self 的生命周期会被赋给所有输出生命周期参数。

例如 fn first_word(s: &str) -> &str 能被自动推导为 fn first_word<'a>(s: &'a str) -> &'a str，所以不需要显式写 'a。

但像 longest 这种返回引用依赖多个输入引用的情况，就必须手动标注。

六、借用检查器做了什么

借用检查器的工作可以概括为一句话：对于每一个引用，验证它的生命周期 ≤ 被引用数据的生命周期。

正是因为这个检查在编译阶段完成，Rust 才能在运行时不引入垃圾回收器，同时保证内存安全。这也是为什么 Rust 被称为“零成本抽象”的重要原因之一。

七、总结

生命周期是 Rust 所有权系统的自然延伸：

  • 每个引用都有生命周期，表示它有效的范围。
  • 引用的生命周期不能超过被引用数据的生命周期。
  • 函数返回引用时，需要用 'a 等泛型生命周期参数标注输入与输出的关系。
  • 结构体包含引用时，也需要生命周期标注。
  • 借用检查器在编译时完成验证，避免运行时悬垂指针。

理解了生命周期，Rust 里最“难啃”的一部分规则就已经掌握得差不多了。
