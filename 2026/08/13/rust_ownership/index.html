Rust所有权学习

Rust 这两年越来越火：连续多年被评为”最受喜爱语言”，也被 Linux、Windows、Android 内核大量采用。为什么大家都说它”安全”？核心就在它的所有权（Ownership）系统——不用垃圾回收，不用手动 free，就能在编译期保证内存安全。

这篇文章用最直观的方式讲清楚 Rust 所有权的三块基石：三条铁律、移动与拷贝、借用与引用。看完你就能看懂大部分 Rust 代码为什么”能编译”或”不能编译”。

如果你是从 C/C++ 或嵌入式转过来，这会是一篇很好的入门地图；如果你是完全新手，也不用怕，我会尽量不用术语绕弯子。

为什么需要所有权

C/C++ 里最常见的内存问题就两类：

  • 内存泄漏：忘了 free/delete；
  • 悬空指针 / 双重释放：内存被释放了还在用，或同一块内存释放了两次。

Rust 的解决办法非常”激进”：给每一块内存安排一个唯一的所有者（owner），并用编译器的规则强行约束——规则遵守不了，程序就编译不过，根本跑不起来。

三条铁律

先记住 Rust 内存安全的三条铁律，后面所有内容都是它们的推论：

  1. 每个值都有一个所有者（owner）；
  2. 同一时刻只有一个所有者；
  3. 所有者离开作用域，值会被自动释放（drop）。

第一眼可能觉得”就这？”，但配合下面的生命周期例子你就明白了：Rust 编译器会在你的作用域结尾自动插入释放代码——你既不需要手动 free，也不会出现忘记释放或释放两次的情况。

注意：Rust 没有垃圾回收器（GC），所有释放逻辑都在编译期生成。运行性能上，它和 C 几乎一样，这也是它适合系统编程的原因。

借用与引用

前面所有权是”拿走”，那如果我只是想读一下、不想搬走呢？这就轮到借用（Borrowing）出场——用 & 传引用，而不是传所有权：

Rust 有两种引用：

写法 含义 限制
&s 不可变引用，只读 同时可以有多个
&mut s 可变引用，可读写 同时只能有一个

函数参数用引用

如果参数直接传 String（不写 &），那 s 的所有权就移交进函数，出来后就不能用了。想读不想搬走，就用 &。

借用两大铁律

  • 铁律一：借用不能超过所有者的生命周期（避免悬空引用）；
  • 铁律二：同一数据同一时刻，要么一个 &mut，要么多个 &，不能混用（避免数据竞争）。

这两条铁律在编译期就被检查，违规直接编译失败。这正是 Rust 能根治 C/C++ 悬空指针和并发数据竞争的根本原因。

直观理解：所有权=房主，引用=借钥匙。房主可以把钥匙借给很多人看（&），但同一时间只能让一个人装修（&mut）。

小结与下一步

这一篇我们掌握了 Rust 最核心的三块拼图：

  • 三条铁律：唯一所有者、自动释放；
  • 移动 vs 拷贝：String 赋值是移动，标量是拷贝，想复制用 .clone()；
  • 借用与引用：& 只读、&mut 可写，编译期检查悬空引用和数据竞争。

所有权是 Rust 的”第一道门槛”，跨过去之后，后面的生命周期（Lifetime）、trait、智能指针（Box/Rc/Arc）都建立在它之上，理解起来会顺畅很多。
