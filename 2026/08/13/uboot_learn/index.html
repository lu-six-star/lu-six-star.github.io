U-Boot学习

学习嵌入式 Linux，Bootloader（引导加载程序）是第一关。而 U-Boot 是嵌入式领域使用最广泛、资料最全的开源 Bootloader。这篇文章从”为什么需要它”讲起，带你完整走一遍 U-Boot 的原理、启动流程、编译、命令和引导内核的过程，适合零基础入门。

为什么需要 Bootloader？

计算机上电后，CPU 的寄存器、内存、串口等都是”原始”状态，不可能直接运行复杂的操作系统。所以需要一个”过渡程序”来：

  • 初始化硬件：设置时钟、初始化 DDR 内存、串口、存储控制器等；
  • 加载系统镜像：把内核镜像从存储介质读到内存中；
  • 引导启动：把控制权交给内核。

这个”过渡程序”就是 Bootloader。在嵌入式 Linux 中，绝大多数方案选用的都是 U-Boot。

U-Boot：全称 Universal Boot Loader，由开源社区维护（DENX 项目），支持 ARM、x86、RISC-V、MIPS 等几乎所有主流架构和五花八门的开发板，是目前事实上的”标准 Bootloader”。

嵌入式 Linux 的完整启动流程

在深入了解 U-Boot 之前，先看清楚它在整个启动链路中的位置。一个典型的嵌入式 Linux 系统启动分为五个阶段：

各阶段的分工：

  1. BootROM：固化在 SoC 内部 ROM 中，上电最先执行，负责从外部存储（SD、NAND 等）的固定位置读取并加载 SPL。
  2. SPL（Secondary Program Loader）：由于 SoC 内部 SRAM 很小，放不下完整的 U-Boot，于是用轻量的 SPL 先初始化 DDR 内存，再把完整的 U-Boot 加载进 DDR。
  3. U-Boot：初始化外设（网卡、MMC、串口等），把内核镜像（zImage）和设备树（dtb）加载到内存，设置启动参数，然后跳转到内核。
  4. Linux 内核：自解压、初始化系统，挂载根文件系统。
  5. 根文件系统：运行 init 进程，启动各种应用程序。

注意：SPL 并不是必须的。如果 SoC 内部的 SRAM 足够大，可以把完整 U-Boot 直接放进 SRAM，跳过 SPL 阶段。现在的 32 位 ARM SoC 大多需要 SPL。

设备树（Device Tree）与 U-Boot

现代嵌入式 Linux 使用设备树（DT, Device Tree）来描述硬件：哪个地址有 UART、GPIO 怎么连、内存多大等，都以文本形式写在 .dts 文件中，编译成 .dtb 二进制后传给内核。这样做的核心好处是硬件描述与内核代码分离，换一块板子往往只需要换 dtb 而不用改内核。

U-Boot 是 dtb 的”搬运工”：它把 dtb 从存储介质加载到内存，然后在启动内核时把 dtb 的地址传给内核。U-Boot 自身也可以使用设备树来初始化硬件（u-boot.dtb）。

提示：设备树里对应的硬件在 U-Boot 阶段和内核阶段是”同一份描述”——所以排查外设问题时，先确认 dtb 是否正确，往往能解决一大半问题。后续学内核时我们会专门展开讲设备树。

U-Boot 如何引导内核（bootm / bootz）

理解了上面这些，U-Boot 引导内核的流程就很清晰了：

  1. 用 tftp / fatload / mmc read 等命令把内核镜像加载到内存（如 0x82000000）；
  2. 把设备树 dtb 加载到内存（如 0x83000000）；
  3. 设置好 bootargs 环境变量；
  4. 执行 bootz 0x82000000 - 0x83000000（zImage 用 bootz，uImage 用 bootm，Image 用 booti）；
  5. 内核接管：自解压、挂载 rootfs、运行 init。

常见问题与注意事项

初学 U-Boot 最容易踩的坑：

  1. 串口没输出：先检查串口波特率（一般是 115200）、接线和 console= 参数是否和板子匹配。
  2. 环境变量改完重启失效：忘了 saveenv。
  3. 启动后没进 Linux：多半是 bootcmd 里的加载地址、文件名或分区写错。
  4. 内核卡住不动：先看 bootargs 里的 console 是否对、root 分区是否存在、dtb 是否匹配。
  5. uImage 与 zImage 混淆：bootz 启动 zImage，bootm 启动 uImage，别用错。
  6. 镜像地址重叠：内核与 dtb 加载地址要错开。

小结与下一步

U-Boot 看似复杂，本质就三件事：初始化硬件、加载镜像、把控制权交给内核。它的命令行和两个环境变量（bootcmd / bootargs）是日常开发与排障的核心。

学完 U-Boot 之后，就可以沿着这条主线继续深入：

  • Linux 内核：学习内核编译、内核启动流程、驱动开发；
  • 设备树（DTS/DTB）：理解硬件描述语法，这是嵌入式 Linux 的重中之重；
  • 根文件系统：BusyBox / Buildroot / Yocto，理解应用运行环境怎么构建。

其中 Buildroot 能一次性帮你生成工具链 + U-Boot + 内核 + 根文件系统，非常适合在 QEMU 或自己的板子上把整个启动链路跑通。下一篇我们就从 Linux 内核 开始讲起。
