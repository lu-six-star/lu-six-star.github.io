蓝牙Mesh学习

蓝牙 Mesh（Bluetooth Mesh）是蓝牙技术联盟（Bluetooth SIG）在 2017 年正式发布的一套基于低功耗蓝牙（BLE）的网状网络规范。它让大量 BLE 设备（灯光、传感器、开关等）可以通过泛洪（Flooding）的方式互相通信，而不需要依赖路由器或中心节点，非常适合智能家居、楼宇自动化等场景。

什么是蓝牙 Mesh？

蓝牙 Mesh 建立在 BLE 的广播（Advertising）机制之上，不需要像经典蓝牙或传统 BLE 那样先建立连接（GATT 连接）再通信。它通过设备之间的消息转发，将信息像水波一样”泛洪”扩散到整个网络，从而实现远距离、多设备、自愈的通信。

它的核心设计理念有几点：

  • 泛洪式转发：任何节点收到消息后，在 TTL 允许的范围内继续转发，不需要路由表。
  • 发布 / 订阅：节点将消息发布到某个”主题”（组地址），只有订阅了该主题的节点才会处理，类似 MQTT。
  • 网络密钥体系：每一层数据都经过加密和认证，安全性由”网络层密钥（NetKey）+ 应用层密钥（AppKey）”双重保障。
  • 对老设备友好：只要设备支持 BLE 4.0 及以上，就可以升级固件支持 Mesh，不强制要求新硬件。

为什么需要蓝牙 Mesh？

传统的 BLE 通信是”一对多”或”一对一”的连接式（GATT）通信，一个主设备（手机）在同一时间只能连接有限个从设备，存在以下限制：

  • 覆盖范围有限：单个 BLE 设备的通信半径通常只有几十米，且不能多跳。
  • 连接数量有限：手机同一时间维护的 BLE 连接数有限，难以控制成百上千个设备。
  • 无法自愈：某个设备掉线后，其余设备可能无法互相通信。

蓝牙 Mesh 正是为了解决这些问题而生的：

  • 多跳扩展覆盖：消息经过中继节点一跳一跳地传递，覆盖范围远超单个设备。
  • 海量设备支持：网络理论上可容纳数千个节点。
  • 去中心化、自愈：网络中不存在单点故障，个别节点离线不影响整体通信。

基本概念

在深入理解 Mesh 之前，先了解几个关键概念：节点、元素、地址、状态与模型、发布/订阅。

节点与元素

一台完成配网的 BLE 设备就是一个节点（Node）。一个节点内部可以包含一个或多个元素（Element），每个元素都拥有自己独立的单播地址。例如一个”三路开关”可以是同一个节点下的三个元素，分别控制三路灯光。

地址类型

Mesh 中一共有三种地址：

地址类型 取值范围 用途
单播地址（Unicast） 0x0001 ~ 0x7FFF 每个元素唯一的地址
虚拟地址（Virtual） 0x8000 ~ 0xBFFF 基于 UUID 生成的地址，语义化
组地址（Group） 0xC000 ~ 0xFFFF 一组设备共享的地址（即”主题”）

注意：节点之间主要靠组地址实现”一对多”的发布/订阅，这也是 Mesh 消息能”点对多点”传输的基础。

状态与模型

状态（State）描述设备当前的情况，比如灯的”开/关（On/Off）”、”亮度（Lightness）”。

模型（Model）是 Mesh 应用层的核心抽象，可以理解为”定义了一组状态和操作消息的接口”，例如：

  • Generic OnOff Server：提供开关状态，能接收开关命令并更新状态。
  • Generic OnOff Client：向 Server 发送开关命令。
  • Light Lightness Server / Client：控制亮度。

模型分为 Client 和 Server 两类，消息在两者之间传递，类似于”服务端提供状态、客户端请求操作”。

发布 / 订阅机制

Mesh 的消息传递采用发布 / 订阅（Publish / Subscribe）模式，与 MQTT 非常相似：

  • 发布（Publish）：节点将消息发布到某个组地址。
  • 订阅（Subscribe）：节点可以订阅一个或多个组地址，收到发给该组地址的消息后才会处理。

例如：三个灯泡都订阅了组地址 0xC001（”客厅灯”），当开关把”开灯”消息发布到 0xC001 时，三个灯泡都会收到并执行开灯动作；而其他未订阅该组地址的节点则直接丢弃消息。

网络架构与节点类型

Mesh 网络中的所有节点地位上是对等的，但根据承担的功能不同，可以分为几种”角色”（同一台设备可以同时承担多个角色）：

节点类型 作用 适用场景
普通节点（Node） 只收发自己关心的消息，不转发 一般传感器、灯具
中继节点（Relay） 将收到的消息转发给其他节点，扩展覆盖 覆盖区域内的”骨干”设备
低功耗节点（Low Power Node, LPN） 平时关闭接收，按需唤醒，大幅省电 电池供电的传感器、门锁
朋友节点（Friend Node） 为 LPN 缓存并转发消息，与 LPN 建立”友谊关系” 长期供电的设备
代理节点（Proxy Node） 通过 GATT 与不支持广播的旧设备/手机通信 手机 App 接入网络的桥梁

消息如何传输（泛洪机制）

蓝牙 Mesh 采用泛洪（Flooding）而非路由表的方式转发消息，大致流程如下：

  1. 发送节点将消息广播出去，消息携带 TTL（初始值由发送方设定，如 3~7）。
  2. 收到消息的中继节点检查：
    • SRC + SEQ 是否已见过（去重，防止死循环）；
    • TTL 是否大于 0。
  3. 若未见过且 TTL > 1，则节点将 TTL 减 1 后重新广播，实现多跳。
  4. 所有收到消息的节点判断 DST 是否命中自己的订阅地址：命中则交给上层处理，未命中则丢弃。

这种机制带来两个特点：

  • 优点：无需维护路由表，实现简单、天然自愈（某条路径失效会自动走其他路径）。
  • 缺点：同一消息会被重复广播多次，网络消息总量和功耗较高。

提示：TTL 并不是越大越好。TTL 越大消息能传得越远，但网内重复广播的次数也越多，容易造成信道拥塞，需要根据网络规模权衡设置。

如何配网（Provisioning）

新设备要加入 Mesh 网络，必须先由配网器（Provisioner）（通常是手机 App）完成配网（Provisioning）。配网的本质是：安全地把网络密钥（NetKey）和单播地址”交给”新设备，使它正式成为网络中的一员。

具体步骤如下：

  1. 设备广播未配网信标（Unprovisioned Device Beacon，类型 0x3F）：未配网设备周期广播广告包，表明”我在这里，等待被配网”。
  2. 建立配网承载（Provisioning Bearer）：配网器与设备建立连接，可通过 PB-ADV（广播承载，设备间直接配网）或 PB-GATT（代理承载，手机等用 GATT 连接配网）。
  3. 交换能力信息（Capabilities）：设备告知配网器自己支持的加密算法、公钥交换方式、OOB 认证能力等。
  4. 配网开始（Provisioning Start）：双方确定使用的算法（通常是 FIPS P-256 椭圆曲线）与认证方式。
  5. 交换公钥，协商会话密钥：双方通过 ECDH 交换公钥，计算出 DHKey 并派生配网会话密钥。
  6. 认证（Authentication）：为防止中间人攻击，通过”输入 6 位数字 / 静态 OOB / 输出 OOB”等方式互相认证（生产环境下强烈建议开启认证）。
  7. 下发配网数据（Provisioning Data）：配网器通过加密通道下发 NetKey、Key Index、设备单播地址、IV Index 等关键信息。
  8. 配网完成（Provisioning Complete）：设备保存密钥与地址，成为正式节点，开始广播 Secure Network Beacon 并参与收发消息。

注意：配网是一次性且极为关键的操作——NetKey 相当于整个网络的”大门钥匙”，一旦泄露，整个网络的安全性都将沦陷。

安全机制

蓝牙 Mesh 在每一层都提供了加密和认证，采用 AES-CCM 加密算法：

  • 网络层：所有节点共享 NetKey，对网络消息进行加密，防止未入网设备窃听、伪造或重放。
  • 传输层：支持分段（Segmentation）与重组，并能对应用数据再次保护。
  • 应用层：不同业务使用不同的 AppKey（应用密钥），实现业务间的隔离，例如”照明系统”和”门锁系统”可以使用不同的 AppKey。

正是这套”NetKey + AppKey”的双层密钥体系，保证了即使某个设备被攻破，攻击者也很难影响到网络中的其他业务。

注意事项

在实际使用蓝牙 Mesh 时，有几个关键点需要特别注意：

  1. 密钥管理：配网信息（NetKey）要妥善保管。换网、丢 Key 的恢复过程很麻烦，建议配网器端做好备份与权限控制。
  2. 广播信道拥挤：Mesh 依赖广播，网络节点越多、消息越频繁，信道拥塞和丢包就越严重，需要合理设计消息频率和 TTL。
  3. 功耗与角色设计：电池设备应设计为 LPN + Friend 的组合来省电；但 Friend 会增加消息时延，不适合对实时性要求很高的控制。
  4. 中继节点数量：中继节点太少覆盖不足，太多则广播风暴加剧，需要按网络规模规划中继设备。
  5. 手机接入依赖 Proxy：传统手机只能走 GATT 连接，因此网络中至少要有代理节点（Proxy），否则手机 App 无法控制网络。
  6. 配网安全：测试环境可跳过认证，但生产环境务必开启 OOB 认证，防止配网阶段被中间人攻击。
  7. 与 Zigbee / WiFi Mesh 的差异：BLE Mesh 是”泛洪式”，无需路由协议、实现简单；Zigbee Mesh 是”路由式”，消息按路由表精确传递，功耗与延迟特性不同，选型时要结合业务场景。

小结

蓝牙 Mesh 是低功耗蓝牙生态向”多对多、去中心化、海量设备”演进的重要一步：

  • 它基于广播 + 泛洪，无需路由器即可多跳通信，天然自愈；
  • 采用发布/订阅模型，配合组地址，实现”一对多”的灵活控制；
  • 通过配网（Provisioning）把新设备安全地引入网络，并依靠 NetKey/AppKey 双层密钥保障安全；
  • 通过 LPN/Friend/Proxy 等节点角色，兼顾了低功耗、覆盖范围和手机接入等多样化需求。

对于智能家居、楼宇控制、传感器网络等场景，蓝牙 Mesh 是一个非常值得关注和选型的技术方案。
