QEMU学习U-Boot实战

上一篇文章讲了 U-Boot 是什么、怎么编译和引导内核。但”纸上得来终觉浅”，最好的学习方式还是动手敲命令。可买一块开发板要花钱、要等、还怕刷坏……有没有办法零成本练手？有，就是 QEMU。

这篇文章带你从装环境开始，一步步在 QEMU 里把 U-Boot 跑起来并交互练习，全程不需要任何真实硬件。

为什么用 QEMU 学 U-Boot？

QEMU 是一个开源的虚拟机/模拟器，它用纯软件模拟一块完整的 ARM 开发板（CPU、内存、串口、网卡等）。用 QEMU 学 U-Boot 有几个实打实的好处：

  • 零成本：不花钱、不用等快递；
  • 不怕刷坏：再怎么折腾也只是在软件里，重启一下就好；
  • 可反复重来：编译、烧录、启动的每一步都可以无限重试；
  • 可调试：支持 GDB 断点单步，这对理解启动过程帮助巨大；
  • 流程与真实板卡一致：编译、加载、命令行交互的体验和真板子几乎一样。

当然，QEMU 不能完全替代真实板子（真实外设、时序、驱动差异还是要去板子上验证），但入门和理解原理已经绰绰有余。

第五步：在命令行交互练习

到了 => 提示符，就可以像在真实板子上一样敲命令了。下面是一组由浅入深的练习。

1. 看帮助和版本

  • help 列出所有可用命令；
  • version 看 U-Boot 版本和编译时间；
  • bdinfo 打印板卡信息（内存起止、启动参数等）。

2. 环境变量练习

setenv 只改内存里的值，重启会丢；在 QEMU 的 virt 板卡上，因为没有挂载存储设备，saveenv 也无法真正持久化——这正好说明”环境变量需要落盘存储”这件事。想练持久化，需要给 QEMU 挂一块虚拟磁盘（进阶部分会提到）。

3. 内存操作练习

md（memory display）和 mw（memory write）是排障神器，比如内核启动失败时，可以先 md 看一下镜像是否真的加载到了指定地址。

4. 其他建议练习

多敲几遍，直到这些命令和输出都熟记于心。

常见问题与注意事项

  1. 没出现 => 提示符：确认用的是 qemu-system-aarch64（不是 qemu-system-x86_64），且 -bios u-boot.bin 路径正确。
  2. 想退出却退不出来：Ctrl+A 然后按 X；在 -nographic 模式下不要用 Ctrl+C，那只会发给 U-Boot 而不是退出。
  3. **编译报 command not found**：工具链没装对，检查 aarch64-linux-gnu-gcc 是否存在，以及 CROSS_COMPILE 拼写。
  4. 命令没生效 / 缺命令：某些命令需要编译时通过配置打开（比如 CONFIG_CMD_*）。用 help 看当前有哪些命令，缺了就去 make menuconfig 打开。
  5. 为什么 saveenv 没用：virt 板卡默认没有存储介质，环境变量只存在”内存”里，重启即丢，这是正常的。
  6. Windows 直接跑可以吗：QEMU 有 Windows 版，但交叉编译工具链在 Windows 下配置麻烦，强烈建议用 WSL。

进阶调试技巧：QEMU 支持 GDB。启动时加 -s -S 参数（暂停 CPU、打开 1234 调试端口），再用 gdb-multiarch 连接 target remote :1234，就可以对 U-Boot 打断点、看寄存器、单步执行。想深入理解启动代码的话，这是必学的利器。

小结与下一步

用 QEMU 学 U-Boot 的完整闭环就是：装环境 → 编译 u-boot.bin → QEMU 加载运行 → 命令行交互练习。它让你以零成本、零风险的方式，把 U-Boot 的启动、命令、环境变量等核心概念全部动手跑一遍。

练熟之后，就可以沿着主线继续：用 Buildroot 跑通”U-Boot 引导内核”的完整链路，然后正式进入 Linux 内核 的学习。
