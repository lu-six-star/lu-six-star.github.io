Linux内核学习

前两篇文章里，我们从零把 U-Boot 跑了起来，又用 QEMU 把整个启动链路打通（U-Boot → 内核 → rootfs → shell）。Bootloader 只是”守门员”，它最终要把控制权交给真正的主角——Linux 内核。

这篇文章系统地讲内核是什么、源码长什么样、怎么编译配置、启动流程怎么走，以及内核空间和用户空间的关系。学完你就能回答：内核到底在做什么？我该从哪儿开始学？

内核在嵌入式系统里的位置

一块板子上电后，整个软件的层次大概是这样的：

层次 作用 例子
应用层 用户业务逻辑 shell、你的 C 程序、QT/小程序
根文件系统 存放程序和数据 Buildroot/busybox 生成的 rootfs
Linux 内核 管理硬件、提供接口 本文主角
Bootloader 初始化硬件并引导内核 前两篇学的 U-Boot
硬件 板子本身 CPU、DDR、外设

内核夹在”硬件”和”应用”中间：向上给应用提供稳定统一的接口，向下直接管理 CPU、内存和各种外设。没有内核，应用就没法安全、高效地使用硬件。

为什么不用裸机（FreeRTOS/裸循环）？嵌入式 Linux 适合功能复杂、需要多任务/网络/文件系统的场景；裸机则适合资源极少、实时性要求极高的场景。两者不是谁替代谁，而是按需求选型。

学内核需要哪些前置基础

如果前面几篇都跟下来了，你的基础已经差不多了。对照检查：

  1. C 语言：内核源码 90% 以上是 C，至少要能看懂函数指针、结构体、链表。
  2. 操作系统概念：进程、内存、中断、文件——不用精通，但要知道它们是什么。
  3. ARM 汇编基础：启动代码里有一点点汇编，认识 bl、ldr、mov 就行。
  4. U-Boot 与启动流程：前两篇已经覆盖，这是理解内核启动的前提。
  5. QEMU + Buildroot 环境：上一篇已经搭好，本篇继续用它做实验平台。

缺哪补哪，但不用等全部精通再开始，边学边补是最快的路径。

源码根目录下子目录很多，但真正核心的就那么几个，别被吓到：

目录 作用 学习优先级
init/ 内核启动入口，start_kernel() 在这里 ⭐⭐⭐ 最先看
kernel/ 进程管理、调度、信号 ⭐⭐⭐
mm/ 内存管理（页表、分配器） ⭐⭐
fs/ 文件系统（VFS 及各种 FS） ⭐⭐
drivers/ 设备驱动（量最大，最常见） ⭐⭐⭐ 做驱动必看
net/ 网络协议栈 ⭐
arch/ 架构相关代码，arch/arm64/ 就是 ARM64 ⭐⭐ 启动时看
include/ 头文件，全内核共享 ⭐⭐ 查结构体用
ipc/、security/、crypto/ 等 其它子系统 用到再学

第一次看源码千万不要按目录从头读到尾。正确姿势：从 init/main.c 的 start_kernel() 开始，跟着启动流程走，遇到哪个子系统再进对应目录查。

配置与编译

1. 先理解：内核是”配置出来的”

内核代码虽然庞大，但你编译时会通过 .config 文件裁剪——用不到的模块根本不会编译进去。这就是内核能适配从路由器到手机各种设备的原因。

三个配置概念先分清：

  • make defconfig：生成一份默认配置（QEMU 虚拟板就用 make ARCH=arm64 defconfig）；
  • make menuconfig：图形化菜单，打开/关闭功能（最常用）；
  • make savedefconfig：把当前配置精简后导出，方便看懂改了什么。

2. 编译

编译产物：

文件 说明
arch/arm64/boot/Image 内核镜像（U-Boot 用 booti 加载）
arch/arm64/boot/dts/.../xx.dtb 设备树二进制（描述板子硬件）
*.ko 可加载的内核模块（驱动等）

提到设备树（DTS/DTB）多说一句：U-Boot 会把设备树传给内核，内核根据它知道板子上有什么硬件。这是 ARM 架构现代启动的标准做法，后面学驱动时它会出现得非常多。

内核启动流程

从 U-Boot 跳转到内核，到 shell 出现，中间发生了什么？对照你保存的启动日志看这张图：

核心链路就 6 步：

  1. U-Boot 跳转：booti/bootm 加载 Image + dtb 到内存，跳到内核入口；
  2. 自解压：实际镜像先解压出真正的内核（压缩的 Image.gz）；
  3. 汇编入口 stext：arch/arm64/kernel/head.S，初始化页表和异常向量，切到 C 语言世界；
  4. **start_kernel()**：init/main.c，一切初始化的起点——打印内核版本、初始化中断/内存/调度器、挂载根文件系统……几百行代码决定了整个系统；
  5. 创建 init 进程：最后 kernel_init() 尝试执行 /sbin/init（或 busybox），这是用户空间第一个进程，PID 为 1；
  6. 移交用户空间：从此内核负责”服务”，shell 和应用正式接管。

建议的源码阅读顺序：init/main.c 的 start_kernel() → 顺着调用往下追（打印版本、setup_arch、mm_init、sched_init……）→ 遇到具体子系统再进对应目录。一个函数一个函数”顺藤摸瓜”，比对着书看快得多。

内核空间 vs 用户空间

启动完成后，系统就分成两个世界了：

  • 用户空间：跑你的应用、shell。程序之间互相独立，谁崩溃都不会搞挂系统；
  • 内核空间：管理进程、内存、文件、网络，并通过系统调用（open、read、write、fork、ioctl…）给用户程序提供服务；
  • 硬件层：真正的 CPU、内存、外设，由内核里的驱动直接操作。

两者通过”系统调用接口”分隔，这是硬件隔离之外最重要的一层安全边界：用户程序不能随便读写硬件，只能通过内核”代办”。

调试方法

调试内核的手段从简单到高级，记住三个字：先日志，再断点。

  1. printk + dmesg：最常用。printk 等级见 /proc/sys/kernel/printk，dmesg 看环形缓冲区；
  2. /proc 和 /sys：内核把运行时信息暴露成文件，cat /proc/cpuinfo、cat /sys/class/... 都是”读内核状态”；
  3. QEMU + GDB：QEMU 启动加 -s -S，gdb-multiarch 连 target remote :1234，可以对内核打断点、看寄存器——这是理解启动流程的终极武器。

在 start_kernel 打断点后单步，结合 init/main.c 源码走一遍，你会把启动流程彻底吃透。

学习路线建议

内核内容无边无际，给你一条能走通的主线：

  1. 跑起来（本篇已完成）：QEMU + Buildroot 跑通整条链路；
  2. 读启动流程：start_kernel() 顺藤摸瓜，配合日志和 GDB；
  3. 补三块基础：进程管理（kernel/）、内存管理（mm/）、VFS 文件系统（fs/）各自的概念性了解；
  4. 写第一个驱动：字符设备驱动（cdev），学会 open/read/write 在驱动的落地；
  5. 学设备树：看懂 .dts，学会在驱动里拿 GPIO、寄存器资源；
  6. 深入某一方向：网络、存储、显示、实时（PREEMPT_RT）……挑一个专项深耕。

别贪多。内核每个子系统都够写一本书，先建立全局地图，再选一个点深挖，是最不劝退的路径。
