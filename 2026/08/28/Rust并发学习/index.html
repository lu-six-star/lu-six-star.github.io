二、消息传递：channel

线程间通信最 Rust 的方式是消息传递——让线程通过 channel 互发消息，而不是直接共享内存：

mpsc 是 multiple producer, single consumer（多生产者单消费者）：可以有多个 tx 发送端（通过 tx.clone() 复制），但只有一个 rx 接收端。recv() 会阻塞等待消息，try_recv() 则立即返回结果。

三、共享状态：Mutex

如果确实要共享数据，Rust 用 Mutex（互斥锁）保证同一时刻只有一个线程能访问数据：

两个要点：

  • Mutex 的 lock() 返回一个可变引用，离开作用域自动解锁——不可能忘了解锁，也不可能同时被两个线程可变访问。
  • Arc（原子引用计数）让多个线程共享同一个 Mutex。普通的 Rc 不能跨线程，因为它的计数不是原子的，有数据竞争风险。

四、Send 与 Sync

Rust 并发安全靠两个标记 trait 保证：

  • Send：该类型的所有权可以跨线程转移。例如 Mutex<T> 是 Send 的（内部已加锁）。
  • Sync：该类型可以被多个线程同时引用（&T 可跨线程共享）。Mutex<T> 是 Sync 的。

几乎所有类型都满足这两个标记，编译器在编译期就检查跨线程的边界——并发错误从运行时的崩溃变成编译期的报错，这是 Rust 最吸引人的特性之一。

五、总结

  • 线程用 thread::spawn + move 闭包创建，join() 等待。
  • 优先用 channel 做消息传递，避免共享状态。
  • 必须共享时用 Mutex + Arc，锁的释放由作用域自动管理。
  • Send / Sync 是编译器层面的线程安全保证。

Rust 的并发模型不提供”万能解药”，但它把最容易出错的共享与通信问题，变成了编译器能检查的规则。写并发代码时，先想想能不能用消息传递，再考虑锁。
