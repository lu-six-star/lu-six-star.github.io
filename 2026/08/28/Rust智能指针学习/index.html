Rust 智能指针学习

一、什么是智能指针

普通引用 &T 只是借用数据，本身不拥有数据；而智能指针不仅持有指向数据的指针，还拥有额外的元数据和行为，比如 Box<T>、Rc<T>、RefCell<T> 等。智能指针都实现了 Deref（让 * 解引用像普通引用一样自然）和 Drop（离开作用域时自动清理）这两个 trait。

二、Box：把数据放到堆上

Box<T> 是最简单的智能指针：它在栈上只保存一个指向堆的指针，数据本体分配在堆上。

Box 最常见的用途有两个：

1. 递归类型。比如链表节点，每个节点里要放”下一个节点”，如果直接写 List 会无限递归导致编译期无法确定大小，用 Box 包一层就固定了大小：

2. 大型数据搬移。把体积很大的数据放到堆上，移动时只复制指针，避免在栈上复制整个数据结构。

三、Deref 与 Drop

智能指针之所以”像引用”，是因为实现了 Deref trait。Box<T> 实现了 Deref<Target = T>，所以 *b 能拿到 T，而且 b.method() 这种写法会自动解引用，非常自然。

Drop trait 则定义了值离开作用域时的清理逻辑。Box 会在 Drop 中释放堆上的内存，我们通常不需要手动调用 drop，编译器会在作用域结束时自动处理。

四、Rc：引用计数共享

所有权规则规定一个值只能有一个所有者，但有些场景确实需要多个部分同时只读地共享同一份数据。Rc<T>（Reference Counting）通过计数来解决这个问题。

关键点：

  • Rc::clone 只是把计数 +1，不会复制数据。
  • 每个 Rc 离开作用域时计数 -1，计数归 0 时才真正释放堆上数据。
  • Rc<T> 只读共享；数据不可变。要修改共享的数据需要配合 RefCell。
  • Rc 是单线程的，多线程要用 Arc<T>。

五、RefCell：内部可变性

借用规则（要么一个可变借用，要么多个不可变借用）默认在编译时检查。RefCell<T> 把检查推迟到运行时，从而允许”共享但可变”——这就是内部可变性。

要注意：编译时检查能提前拦截问题；RefCell 的运行时检查在违规时会直接 panic!，所以要用得小心。

六、总结

智能指针 作用 可变性 所有权
Box<T> 堆上分配 有（独占） 单所有者
Rc<T> 引用计数共享 无 多所有者（只读）
RefCell<T> 运行时借用检查 有（内部可变） 单所有者
Rc<RefCell<T>> 共享且可变 有 多所有者（单线程）
Arc<Mutex<T>> 多线程共享 有 多所有者（多线程）

智能指针把”手动管理内存”这件 C/C++ 里最容易出错的事，变成了类型系统的一部分，编译器会在编译期（或运行时）替你盯着。
