Rust 泛型与 Trait 学习

一、为什么需要泛型

泛型让我们写一次代码，就能适用于多种类型。没有泛型时，每个类型都要重复写一遍逻辑；有了泛型，可以合并成一个函数：

T 是一个类型占位符，调用时才确定具体类型。编译器在编译期会把 T 替换成实际类型并生成对应代码，这个过程叫单态化（Monomorphization）。

二、泛型结构体

泛型也能用于结构体，最典型的就是 Option<T> 和 Result<T, E>：

这两个类型几乎出现在所有 Rust 代码里：Some(5)、Ok("ok")、Err("boom")。泛型把它们定义成”通用的容器”，而具体装什么类型由使用方决定。

三、Trait：定义共享行为

泛型解决”类型不同、逻辑相同”的问题；Trait 解决”类型不同、行为相同”的问题。trait 定义一组方法的签名，让不同类型分别实现：

四、常见的标准库 Trait

  • Display：用 {} 格式化输出。
  • Debug：用 {:?} 调试输出（可用 #[derive(Debug)] 自动实现）。
  • Clone：深拷贝（#[derive(Clone)]）。
  • Copy：按位复制（配合 Clone）。
  • PartialEq / Eq：比较相等（==）。
  • From / Into：类型转换，比如 String::from("hi")。

写自己的类型时，能用 #[derive(...)] 直接生成的就别手写，省事又不易错。

五、静态分发与动态分发

trait 作为函数参数有两种写法：

  • impl Trait：编译期确定具体类型，单态化展开，零开销。
  • dyn Trait（trait 对象）：运行期通过虚表（vtable）跳转，需要 & 或 Box 包裹，灵活但有一点开销，可放入异构容器。

简单取舍：类型在编译期就确定 → 用 impl Trait；运行期类型多样、需要放进 Vec<Box<dyn T>> → 用 dyn Trait。

六、总结

  • 泛型 + 单态化 = 一套逻辑多种类型，零抽象开销。
  • Trait = 行为契约，把”能做什么”抽象出来。
  • impl Trait（静态分发）vs dyn Trait（动态分发）= 性能与灵活性的取舍。
  • 标准库的派生 trait（Debug、Clone、PartialEq 等）让代码更简洁。

泛型和 trait 是 Rust 抽象能力的核心，几乎所有库的 API 都建立在它们之上。理解之后，读 Rust 生态的代码会轻松很多。
