Rust 错误处理学习

一、两种错误：panic! 与 Result

Rust 把错误分成两类：

  • 不可恢复的错误：比如数组越界、栈溢出，用 panic! 宏直接终止线程。
  • 可恢复的错误：比如文件不存在、网络超时，用 Result<T, E> 把错误作为值返回，让调用者决定怎么办。

和 C++/Java 的异常不同，Rust 的错误写在类型签名里——调用一个可能失败的函数，返回值会强迫你面对错误，不存在”忘了写 try-catch”这回事。

二、Option：可能没有值

Option<T> 可以看作 Result 的”轻量版”，表示”可能有值，也可能没有”，用来代替其他语言里的 null：

Rust 里没有空指针，想表示”缺失”就必须用 Option，编译器会逼着你处理 None 的分支。

总结：

  • panic! 处理不可恢复错误，Result 处理可恢复错误，Option 处理缺失值。
  • match 是最基本的解包方式，分支必须穷尽。
  • ? 把”传播错误”变成一行代码，是 Rust 错误处理的灵魂。

Rust 的错误处理初看繁琐，但它把”错误可能发生”写进了类型系统：编译器替你检查每一条路径，运行时就少了很多意外。
