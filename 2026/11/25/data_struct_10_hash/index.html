数据结构（十）：哈希表 —— 数组与链表的合体

哈希表 = 数组的随机访问 + 链表的碰撞处理。本篇手写一个 8 桶拉链法哈希表，把 10 个键塞进去，实测碰撞链长、空桶分布与查找过程，看”均摊 O(1)”到底从哪来。

一、结构：桶数组 + 拉链

djb2 是最经典的字符串哈希之一：hash = (hash << 5) + hash + c 等价于 hash * 33 + c，一个循环把任意字符串摊到 0~7 的桶号上。

二、实验：10 个键塞进 8 个桶

实测读出的信息量：

  1. 碰撞真实发生：10 个键、8 个桶，桶 0、6、7 各挂了 2 条——peach 和 banana 撞在桶 6，靠链表共存；
  2. 空桶也真实存在：桶 3 空着——哈希不可能完美均匀；
  3. 查找的 O(1) 从哪来：get("grape") 只扫了桶 4 的一条链就命中——先哈希定位把搜索空间缩小到 1/8，再在短链上线性扫。负载因子（元素数/桶数）越低，链越短，越接近 O(1)；
  4. 头插新元素：peach 插在桶 6 的链头（banana 之前）——拉链法 O(1) 插入的标准姿势。

三、负载因子与扩容

负载因子 = 元素数 ÷ 桶数。本例 10/8 = 1.25——每个桶平均挂 1.25 条。工程经验：负载因子超过 0.7~1.0 就该扩桶（翻倍 + 全部重新哈希）。本实验刻意不扩容，让你看到”桶太少时链子变长”的样子——链一长，哈希表退化成链表。

四、踩坑记录

  1. 哈希函数质量决定一切——分布不均的哈希让所有键挤进一个桶，直接退化 O(n)；djb2/FNV 是简单场景的好起点；
  2. 键的生命周期——Entry 里存的是键的拷贝（strncpy），如果存指针必须保证键内存长效（第 5 篇 FreeRTOS 系列讲过的指针坑）；
  3. 删除要摘链——找到前驱才能摘节点，或者用”值替换 + 删后继”的技巧；
  4. 扩容要重新哈希——桶数变了，每个键的桶号全变，必须遍历所有链重插（rehash）。

五、小结与下一篇预告

  • 哈希表 = 数组（O(1) 定位桶）+ 链表（桶内碰撞拉链）；
  • 实测：10 键 8 桶，最深链 2 层，未命中也只扫一个桶；
  • 负载因子是健康指标，超阈值就 rehash 扩容；
  • 拉链法 = 数组与链表优势互补的典范。
