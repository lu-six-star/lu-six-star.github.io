数据结构（五）：结构体进阶 —— union、位域与柔性数组

结构体的三个”贴着内存做设计”的进阶工具：union 用一份内存看穿大小端（实测字节序 04 03 02 01）、位域把 4 个字段压进 16 bit（实测 0xEAAD）、柔性数组让”头部 + 变长数据”一次 malloc 搞定。全部真机实测。

一、union：一份内存，多个视角

union 的所有成员共用同一块内存，sizeof 取最大成员。用它当”内存体检仪”：

实测输出：

同一个 0x01020304，按 4 字节读是它自己，按 4 个单字节读出 04 03 02 01——低地址存低位字节，这就是小端序（x86/ARM 默认）。大小端问题（网络字节序、多机通信、寄存器拆分）从此有了亲眼可见的验证手段。写一个成员、另一个跟着变——union 的本质是”对同一块内存的多种合法解释”。

二、位域：把 4 个字段压进 16 bit

赋值 a=5、b=21、c=42、d=3，memcpy 出原始 uint32 实测：

0xEAAD = 1110 1010 1010 1101——按位拆开：低 3 位 101(=5) 是 a，接下来 5 位 10101(=21) 是 b……位域让编译器自动生成位运算，寄存器映射、协议头、布尔组标志都靠它省 RAM。注意：位域的跨字节布局由编译器决定，跨平台协议要用显式移位而非位域。

四、踩坑记录

  1. union 的多成员并发使用是未定义行为——写 A 读 B 属于类型双关（type punning），实测能跑但严格说依赖实现；跨平台代码用 memcpy 读写更稳；
  2. 位域的位序不可移植——a 在低 3 位是本机现象，换编译器/端序可能颠倒；跨平台协议用移位+掩码；
  3. 柔性数组的边界——分配多大就用多大，越界写 data 就是堆溢出；len 字段要和数据一起维护；
  4. 柔性数组必须放结构体最后，且结构体至少还要有一个其他成员。

五、小结与下一篇预告

  • union = 同一块内存的多重解释，4 字节看穿大小端；
  • 位域 = 编译器代劳的位打包，16 bit 塞下 4 个字段（0xEAAD 实测）；
  • 柔性数组 = 头部与变长数据一次分配（malloc(13) 实测）；
  • 三件套的共同精神：贴着内存布局做设计。
