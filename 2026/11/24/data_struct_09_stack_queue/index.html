数据结构（九）：栈与队列 —— LIFO 与 FIFO 的工程实现

栈和队列是”受限的线性表”：只允许在一端操作，却换来 O(1) 的确定性。本篇实验重点是循环队列——5 格队列入满、出 2、再入 2，亲眼看 head/tail 下标取模回绕（”60”落在了物理下标 0 上），以及 FreeRTOS 队列同源的”空/满判断”问题。

注意 head=2 tail=2 且 count=5（满）——如果只看 head==tail 会误判为”空”，空/满歧义必须解决。

三、空/满判断的三种流派

  1. count 计数器（本实验）：最直观，入队出队各多一次运算；
  2. 牺牲一个格子：head==tail 为空、(tail+1)%cap==head 为满——省掉 count，代价是有效容量少一格；
  3. 布尔标志：额外存一个 last_op_was_full。

FreeRTOS 的 xQueue 内部正是环形缓冲思想：满时发送任务挂到”等待写入列表”睡眠（第 5 篇实验 7 的背压），空时接收任务挂到”等待读取列表”——数据结构相同，只是把”返回失败”升级成了”阻塞唤醒”。

五、踩坑记录

  1. 取模运算符对负数——C 的 % 对负数结果为负，队列下标永远用无符号/保证先加后模；
  2. count 与 head/tail 不同步——临界区外多任务操作环形缓冲（第 12 篇的竞态）照样会撕数据；
  3. 栈溢出——顺序栈满了继续 push 是缓冲区溢出，写之前查 iTop；
  4. 队列出空再出——先判 count，否则读到陈旧数据。

六、小结与下一篇预告

  • 栈：一根指针的 LIFO，函数调用帧的本体；

  • FreeRTOS xQueue = 环形缓冲 + 阻塞唤醒列表——本篇的数据结构 + 第 5 篇的机制。
