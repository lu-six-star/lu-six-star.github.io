数据结构（八）：双向链表与循环链表 —— 哨兵节点

单链表的三个不爽：只能单向走、删除要找前驱、头节点是特例。解法：prev 指针 + 哨兵节点。本篇实测：带哨兵的双向链表删除不存在的元素也安全，反向遍历一步到位；循环链表走 12 步自动回绕——FreeRTOS 的 list.c 用的正是这套结构。

一、哨兵节点：消灭所有特例

先造一个不存数据的假节点（哨兵），让它永远站在链表最前面，prev/next 指向自己（空表自环）：

从此之后，”第一个真节点”和”中间节点”的插入删除代码完全一样——没有”链表为空”的特判，没有”删的是头”的特判。这就是工程链表（包括 FreeRTOS list.c）都用哨兵的原因：宁多一个假节点，省掉一堆边界 if。

三、循环链表：尾巴牵着脑袋

循环结构没有 NULL 尾巴，遍历的终止条件从 p != NULL 变成”回到出发点”——轮询调度、轮转任务、环形缓冲都是它的形状。FreeRTOS 的时间片轮转，靠的就是链表 pxIndex 指针在循环列表里”从上次的位置继续走”。

四、踩坑记录

  1. 循环链表忘了终止条件——遍历写成 p != NULL 就是死循环，必须”回到起点即停”；
  2. 哨兵也会被误删——遍历终止条件写错时，哨兵会被当数据处理，务必理解”哨兵是结构的一部分”；
  3. 双向链表删除顺序——先接后继再 free，两根指针都要摘干净；
  4. 空表判断——哨兵方案下 sentinel->next == sentinel 即空表，这个约定要贯穿所有函数。

五、小结与下一篇预告

  • 哨兵节点消灭特例，prev 指针换来自由——实测删除不存在元素也安全；
  • 双向 = O(1) 删除当前节点 + 双向遍历；循环 = 天然轮转；
  • 这两个特性组合（双向 + 循环 + 哨兵 + 排序），正是 FreeRTOS 内核链表的完整配方——第 11 篇去读真源码。
