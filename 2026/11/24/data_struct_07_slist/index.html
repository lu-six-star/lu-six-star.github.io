数据结构（七）：单链表 —— 指针串起来的散装节点

数组的痛点在上一篇已经实测：中间插入要整体搬家。链表反其道而行——每个节点独立 malloc、靠 next 指针牵手，插入删除只改指针。代价是失去随机访问。本篇完整实现头插/尾插/查找/删除/反转，全部实测输出。

三个值得注意的实测细节：

  1. 节点地址不连续（A40 与 BA0 相差 0x160）：每个节点独立 malloc，散落在堆的各处——和数组的紧凑连续形成鲜明对比；
  2. 反转后 3 -> 1：三指针（prev/cur/next）原地推进，把每根 next 指针掉头，O(n) 完成、零额外内存；
  3. **删除是”跨接”**：前驱的 next 直接指向被删节点的 next，然后 free——指针一改，节点就”出局”了。

三、复杂度对照（数组 vs 链表）

操作 数组 单链表
随机访问第 i 个 O(1) O(n)
头部插入/删除 O(n) 整体搬家 O(1)
尾部插入 均摊 O(1) O(n)（无尾指针时）
按值查找 O(n)（无序） O(n)
内存开销 紧凑，无额外 每节点多一个指针

选择口诀：频繁随机读用数组；频繁增删（尤其头尾）用链表；两者都要，看数据量级和缓存敏感性（数组对 CPU 缓存友好，链表节点散落缓存不友好——这也是为什么工程上 vector 经常打赢 list）。

四、踩坑记录

  1. 释放链表的顺序——必须先用临时变量存 next 再 free 当前节点，free 完再访问 pxNext 就是 use-after-free；
  2. 头节点特例——删除头节点时”前驱”不存在，要么特判要么用二级指针/哨兵节点（下一篇的哨兵就是为消灭特例而生）；
  3. malloc 不判 NULL——节点分配失败直接解引用崩溃；
  4. 修改 head 忘了传二级指针——函数内改的是副本，调用者的 head 纹丝不动，”为什么插入没生效”的经典问题。

五、小结与下一篇预告

  • 节点独立 malloc + next 牵手 = 插入删除 O(1)、随机访问 O(n)；
  • 反转 = 三指针原地掉头，面试高频但本质朴素；
  • 二级指针操作头节点是 C 链表代码的关键技巧；
  • 头节点特例、单向不可回头——这两个不便之处，下一篇用哨兵节点 + prev 指针一并解决。
