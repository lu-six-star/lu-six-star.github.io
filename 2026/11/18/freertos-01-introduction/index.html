FreeRTOS 学习笔记（一）：初识 FreeRTOS —— 从裸机到多任务

本系列是在 Windows 仿真环境下学习 FreeRTOS 的完整笔记：不需要开发板，跟着做就能跑通每一行代码。这是第一篇，先把”为什么需要 RTOS”这件事讲透。

一、从一个裸机工程师的深夜说起

我写过的第一段单片机程序，大概是这个样子的：

大循环叫后台，中断服务程序叫前台——所以这种架构又叫”前后台系统”。它能跑，功能也不少，但写着写着就开始难受了：

  1. 响应时间不可预测。用户按下按键，最坏要等大循环跑完剩下三步才被 check_button() 扫到。一旦某个环节加了耗时代码，整圈循环全部变慢。
  2. 一个阻塞，全部趴窝。如果 read_sensor() 里要等待传感器就绪，整个循环卡在那里，显示、按键全部停摆。
  3. CPU 大量时间在空转。等待外设、软件延时，这些时间 CPU 什么正事都没干。

功能一多，while(1) 里堆满状态标志位和互相调用的函数，改一处、崩一片。

二、RTOS：不是”更快的系统”，而是”确定的系统”

很多人第一次听到”实时操作系统”，以为是”跑得特别快”。实时（Real-Time）的核心不是快，而是确定——在承诺的时间内完成响应，无论程序此刻在干什么。

  • 硬实时：错过期限就是事故，如安全气囊、电机控制；
  • 软实时：偶尔超时可以接受，如界面刷新、日志上报。

RTOS 的解题思路很直接：把每个功能变成一个独立的任务（Task），交给调度器（Scheduler）统一调度。谁该跑谁跑，谁在等待就让出 CPU。上面那些痛点，本质都从”程序结构”上升到了”操作系统机制”层面。

三、FreeRTOS 是什么

如图：裸机是”所有功能排成一队循环执行，中断随时插队”；FreeRTOS 则是”调度器把 CPU 时间切成细小的片段，按优先级分配给三个任务”——每个任务都以为自己独占了 CPU。

FreeRTOS 是目前应用最广的开源实时操作系统内核，特点非常鲜明：

  • 完全免费，MIT 许可证：可以闭源商用，产品里用它不需要公开自己的代码；
  • 内核极小：核心就是几个 .c 文件，典型配置下 ROM 占用 6~10KB 起、内核 RAM 几百字节起，8 位机到 32 位机都能塞下；
  • 移植层丰富：官方支持 40+ CPU 架构，从 STM32、ESP32 到 RISC-V 都有现成的移植；
  • 生态成熟：2017 年起由 Amazon 接手维护，配套 FreeRTOS+TCP、+FAT 等中间件，还有 AWS IoT 集成。

对照上图记住四个刚登场的名词，后面每一篇都会用到：

名词 一句话解释
任务 Task 一条独立的执行流，有自己的栈和优先级，对应一个函数
调度器 Scheduler 决定”此刻该运行哪个任务”的内核代码
心跳 Tick 周期性定时中断，是调度器的时间基准（默认 1ms 一次）
上下文切换 Context Switch 切换任务时保存/恢复寄存器的过程，代价只有几微秒

四、源码结构一览：内核其实很小

打开 FreeRTOS 源码，内核部分只有这么几个文件：

文件 职责
tasks.c 任务管理与调度核心，内核的”心脏”
list.c 链表实现，调度器所有数据结构的基石
queue.c 队列，同时也是信号量、互斥量的底层实现
timers.c 软件定时器
event_groups.c 事件组
stream_buffer.c 流缓冲区 / 消息缓冲区
croutine.c 协程（老特性，新项目很少用了）
portable/ 移植层：与编译器、CPU 架构相关的代码

有两点值得划重点：

  • list.c 是地基。就绪任务、阻塞任务、延时任务全靠几条精心设计的链表管理，读懂它，调度器就不再神秘；
  • queue.c 身兼数职。二值信号量、计数信号量、互斥量都是”特殊的队列”，后面学同步机制时会反复回到这个文件。

portable/ 目录则解释了 FreeRTOS 为什么能无处不在：与硬件相关的部分被隔离在这里，换芯片只需要换对应的移植文件，内核一行不用改。

五、初学者常见误区（提前避坑）

  1. “FreeRTOS 是个操作系统”——只对了一半。它是 RTOS 内核：只有任务调度、内存管理这些机制，没有驱动、文件系统和网络栈。需要这些能力时要用 FreeRTOS-Plus 中间件或者自己移植。
  2. “用了 RTOS 程序就自动实时了”——不会。优先级设计不合理，高优先级任务照样可能霸占 CPU，把低优先级任务饿死。实时性是设计出来的，不是 RTOS 白送的。
  3. 分清三个名字：FreeRTOS 是本尊；OpenRTOS 是早期商业发行版的旧称；SafeRTOS 是同一内核经安全认证的商业版本，别混为一谈。
  4. 版本焦虑没必要。目前内核主线是 v11.x，网上大量教程基于 v9/v10，核心 API 几乎没变；个别文件位置有调整，遇到时查一下官方文档即可。

六、小结与下一篇预告

这一篇我们搞清楚了三件事：

  • 裸机前后台系统的三个痛点：响应不可预测、互相阻塞、CPU 空转；
  • RTOS 的价值在于确定的响应时间，把功能拆成任务交给调度器管理；
  • FreeRTOS 内核小、许可证宽松、生态成熟，tasks.c + list.c + queue.c 是它的三大件。

下一篇我们动手：在 Windows 上用官方仿真移植跑起 FreeRTOS——不用买开发板，用 xTaskCreate() 创建两个任务，看着它们在同一个 while(1) 都不存在的世界里交替打印。
