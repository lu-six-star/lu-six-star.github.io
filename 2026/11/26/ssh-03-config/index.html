SSH 学习笔记（三）：把一长串参数变成 ssh lab，顺带搞定跳板机

上篇把免密登录跑通了，但命令也越敲越长：ssh -i ~/.ssh/lab_ed25519 -p 2222 -o StrictHostKeyChecking=accept-new chris@127.0.0.1。每次都要从历史里翻，换台机器、加个跳板，参数又得重排。

这一篇就干一件事：把这一长串收进 ~/.ssh/config，让 ssh lab 一条命令搞定。顺带把两个最容易踩的坑踩给你看——Host * 到底该写在哪、ProxyJump 为什么有时候连不上。文中所有 ssh -G 解析结果、跳板机日志，全部本机实测。

一、痛点：每次都要敲一长串

接上一篇的靶机，直连一条命令是这样的：

参数散落在命令行里，换个端口、换把密钥、加个跳板，整条命令都要改。更糟的是这些参数无法复用——脚本里写一遍，交互式终端里又得敲一遍。

~/.ssh/config 就是用来解决这个的：把”连接谁、用什么身份、走哪条路”全部固化成具名的 Host 块，之后只敲别名。

二、最小可用版：一个别名

之后 ssh lab 就等价于上面那一长串。scp file.txt lab:~/、rsync -av ./ lab:~/code/ 全都自动继承。

几个常用项速查：

配置项 作用
HostName 真实地址（IP 或域名），Host 只是别名
Port 非 22 端口时必填
User 登录用户名
IdentityFile 私钥路径，多把时每行一个
IdentitiesOnly yes 只用上面指定的密钥，不四处乱试（排障神器）
ProxyJump 跳板机，详见第四节

三、原理：配置到底听谁的——先匹配先赢

这是 config 里最反直觉、也最容易踩坑的一条规则。很多人以为”越具体的 Host 越优先”，或者”写在后面的覆盖前面的”，都不对。

OpenSSH 对配置文件的处理是：从头到尾扫描，对每一个单值参数，取第一个匹配该主机的块里的值。也就是 first-match-wins，先到先得。

这里还有一个值得记住的细节：identityfile 在版本 A 里出现了两个。因为 IdentityFile 是多值参数，会累加，不适用 first-match 规则；而 Port、User、HostName 是单值，取第一个匹配。所以口诀是：

单值参数先匹配先赢，Host * 永远放最后；IdentityFile 会累加，别被它迷惑。

四、多主机与跳板机：ProxyJump

公司内网的机器往往不能直连，得先登跳板机再跳进去。手动做法是 ssh jump 进去，再在跳板上 ssh target——两层密码、两次认证，还没法直接 scp。

ProxyJump 把这两步合成一条：本地先连跳板，在跳板的连接里开一条隧道直达目标，认证和命令都在本地完成。

五、用 ssh -G 验收最终配置

改完 config，别急着连，先用 ssh -G 看一眼最终生效的配置。它不发起连接，只打印解析结果：

一眼就能确认 port 是不是 2222、proxyjump 有没有生效、identityfile 指对没有。排障时这是第一条命令——很多”连不上”其实在 ssh -G 阶段就已经露馅了。

通配符还能批量管理：Host 10.0.0.* 匹配一个网段，Host *.example.com 匹配一个域名后缀，但依然服从 first-match-wins，具体块要写在通配块前面。

六、踩坑记录

  1. Host * 写在最前面：单值参数（Port/User/HostName）会被它抢先命中，后面的具体 Host 全部失效。永远把 Host * 放最后。
  2. 命令行 -o 不传给 ProxyJump 子进程：ssh -o UserKnownHostsFile=x target 只对主连接（target）生效，连跳板 jump 的子进程读的是 config 里的值。所以 UserKnownHostsFile、StrictHostKeyChecking 这类选项要写进 config 的 Host *，别只写在命令行。本篇第一次跑跳板时就栽在这——jump 的主机密钥验证去读了默认的 ~/.ssh/known_hosts，导致隧道里 banner exchange 超时。
  3. IdentityFile 累加不是 bug：看到 ssh -G 里有多把密钥别慌，那是设计如此；要强制只用指定的一把，加 IdentitiesOnly yes。
  4. 跳板机本身也要能登录：ProxyJump jump 要求 jump 块配置完整（地址、端口、密钥），否则第一段就过不去，报的错看起来像 target 连不上，根因却在 jump。
  5. **ProxyJump vs ProxyCommand**：ProxyJump 是 ProxyCommand + ssh -W 的语法糖，99% 场景用 ProxyJump 就够；只有需要自定义代理（比如套 nc、过 HTTP 代理）时才写 ProxyCommand。

七、小结与下一篇预告

三句话收尾：

  • config 是连接参数的具名封装：ssh lab 背后是一整组 HostName/Port/User/IdentityFile，别名只是入口。
  • 优先级记住 first-match-wins：单值参数取第一个匹配块，Host * 放最后兜底；IdentityFile 是多值会累加。
  • ProxyJump 一步到位：本地连跳板、跳板开 direct-tcpip 隧道到目标，认证和命令都在本地完成；(via proxy) 是它在日志里的签名。

下一篇打开 SSH 的另一个超能力：端口转发。一条 ssh -L 能把内网服务”搬”到本地，-R 能把本地服务”暴露”到远程，-D 直接开一个 SOCKS 代理让流量从远程出去。同样用本机靶机把三种隧道跑通，抓日志看清楚每种转发到底是谁在监听、谁在连目标。
